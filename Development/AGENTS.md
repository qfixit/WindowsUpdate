## Project Structure & Module Organization
- Root PowerShell entry point: `Windows11Upgrade.ps1` orchestrates staging, toast notifications, reminder tasks, post-reboot validation (RunOnce), and self-repair using helpers such as `MainFunctions.ps1`, `Detection.ps1`, `IsoDownload.ps1`, `SystemChecks.ps1`, `ScheduledTasks.ps1`, and `SelfRepair.ps1`.
- Configuration emitters live in `UpgradeConfig.ps1` and `UpgradeConfig-RMM.ps1`; version stamp is tracked in `Version.txt`.
- Toast assets/scripts sit under `Toast-Notification`; keep `hero.jpg`, `logo.jpg`, and toast scripts aligned with the orchestrator.
- `Documentation/README.md` holds the technicians' guide and changelog.
- Error codes and remediation are cataloged in `ErrorCodes.ps1`.

## Versioning and Date Requirements
- Every time this file is modified, update both the Version (# Version X.Y.Z) and Date (# Date MM/DD/YYYY) in the header of the relevant script.
- Versions use a three-number semantic format: Major.Minor.Patch.
- Patch and Minor increments are chosen at the agent’s discretion based on scope; Major changes are technician-approved.
- The Date must reflect the current date when changes are made.

## Build, Test, and Development Commands
- All scripts must be PowerShell 5 compatible.
- This package deploys at scale; keep unattended-safe defaults.
- Testing is handled by the technician on a Windows 10 VM snapshot that can be reverted.

## Coding Style & Naming Conventions
- Preserve marker filenames (`ScriptRunning.txt`, `PendingReboot.txt`, `UpgradeFailed.txt`) under `C:\Temp\WindowsUpdate`.
- Keep logging consistent and actionable across scheduling, ISO handling, and cleanup.
- File names follow PascalCase with hyphens for script entry points (e.g., `Start-Windows11Upgrade.ps1`).
- Refer to `Development/powershell.instructions.md` for detailed conventions.

## Testing Guidelines
- Technician-driven; review `Windows11UpgradeLog.txt` after runs. Ask for more context if needed.

## Commit & Pull Request Guidelines
- Use short, imperative commit messages.
- PRs should describe scenario, behavior change, rollout impact, and manual test evidence (logs/task outputs/toast screenshots).
- Call out risk areas (reboot gating, task creation, ISO download paths) for targeted validation.

## Security & Configuration Tips
- Do not embed secrets. Config is supplied via `config.json` generated by `UpgradeConfig-RMM.ps1` (no runtime defaults).
- When altering paths/assets, ensure helper functions and toast scripts align before merging.
